# Kế Hoạch Sửa Lỗi & Cải Thiện Dự Án `sharedocu`

## Tổng quan

Kế hoạch này gồm **8 bước chính**, chia theo **3 mức ưu tiên**: High, Medium, Low.
Mỗi bước thực hiện tuần tự để tránh xung đột.

---

## Pha 1: Critical (High Priority) — Sửa gấp

### Bước 1: Externalize API URL sang Environment Config

**Vấn đề:** API URL `http://10.0.2.2:5000/api/auth` hardcoded ở `AuthContext.tsx:4`, được import từ 6+ file. Không chạy được trên device thật, iOS, hoặc production.

**File cần sửa:**

- `src/config/env.ts` (tạo mới)
- `src/context/AuthContext.tsx`
- `src/screens/ScannerScreen.tsx`
- `src/screens/ShareFormScreen.tsx`
- `src/screens/ProfileScreen.tsx`
- `src/screens/LoginScreen.tsx`
- `src/screens/RegisterScreen.tsx`
- `src/screens/HistoryScreen.tsx`
- `package.json` (thêm dependency)

**Cách thực hiện:**

1. Cài `react-native-dotenv` hoặc `react-native-config`
2. Tạo file `.env` với nội dung:
   ```
   API_URL=http://10.0.2.2:5000/api
   ```
3. Tạo `src/config/env.ts`:
   ```typescript
   export const API_URL = process.env.API_URL || 'http://10.0.2.2:5000/api';
   export const AUTH_URL = `${API_URL}/auth`;
   export const DOCUMENT_URL = `${API_URL}/documents`;
   export const SYNC_URL = `${API_URL}/sync`;
   ```
4. Thay thế tất cả các import `API_URL` từ `AuthContext` sang từ `config/env.ts`
5. Tính `DOC_URL` trong mỗi file dựa trên `DOCUMENT_URL` config thay vì `.replace('/auth', ...)`

### Bước 2: Thêm logic kiểm tra Token Expiry trong AuthContext

**Vấn đề:** Token lưu trong AsyncStorage không có hạn dùng. Nếu backend revoke token, app vẫn dùng ngầm.

**File cần sửa:**

- `src/context/AuthContext.tsx`

**Cách thực hiện:**

1. Mở rộng interface `AuthContextType`:
   ```typescript
   login: (token: string, user: User, expiresIn?: number) => Promise<void>;
   isTokenExpired: () => boolean;
   ```
2. Khi `login`, lưu thêm `tokenExpiry` vào AsyncStorage (dựa trên `expiresIn` của backend hoặc mặc định 7 ngày)
3. Trong `loadStorageData`, sau khi đọc token, kiểm tra:
   ```typescript
   const expiry = await AsyncStorage.getItem('tokenExpiry');
   if (expiry && Date.now() > parseInt(expiry)) {
     // Token hết hạn, auto-logout
     return;
   }
   ```
4. Export thêm hàm `isTokenExpired` để các màn hình khác có thể kiểm tra trước khi gọi API

### Bước 3: Fix Animation Memory Leak trong ScannerScreen

**Vấn đề:** `Animated.loop` được `start()` nhưng không có cleanup khi component unmount → memory leak.

**File cần sửa:**

- `src/screens/ScannerScreen.tsx`

**Cách thực hiện:**

1. Chỉnh sửa `useEffect` ở lines 452-468:
   ```typescript
   useEffect(() => {
     const pulseLoop = Animated.loop(
       Animated.timing(pulseAnim, { ... })
     );
     const bounceLoop = Animated.loop(
       Animated.sequence([
         Animated.timing(bounceAnim, {...}),
         Animated.timing(bounceAnim, {...}),
       ])
     );
     pulseLoop.start();
     bounceLoop.start();

     return () => {
       pulseLoop.stop();
       bounceLoop.stop();
     };
   }, []);
   ```

### Bước 6: Thêm Authorization Header vào downloadFile

**Vấn đề:** `downloadFile` không gửi Authorization token khi tải file → 401 nếu file yêu cầu đăng nhập.

**File cần sửa:**

- `src/screens/ScannerScreen.tsx`

**Cách thực hiện:**

1. Sửa hàm `downloadFile` (line 191-217):

   ```typescript
   const downloadFile = async (url: string, fileName: string, authToken?: string) => {
     const { dirs } = ReactNativeBlobUtil.fs;
     const path = Platform.OS === 'ios'
       ? `${dirs.DocumentDir}/${fileName}`
       : `${dirs.DownloadDir}/${fileName}`;

     try {
       const headers: Record<string, string> = {};
       if (authToken) {
         headers['Authorization'] = `Bearer ${authToken}`;
       }

       const res = await ReactNativeBlobUtil.config({
         fileCache: true,
         addAndroidDownloads: { ... }
       }).fetch('GET', url, headers);

       Alert.alert("Success", `File saved to: ${res.path()}`);
     } catch (error) {
       console.error(error);
       Alert.alert("Error", "Download failed.");
     }
   };
   ```

2. Sửa lời gọi trong `checkPasswordAndDownload` và chỗ gọi trực tiếp:
   ```typescript
   await downloadFile(data.downloadUrl, docName, token);
   ```

### Bước 7: Fix logic `ShareFormScreen` — `reject` undefined & duplicate `setIsLoading`

**Vấn đề:** `setIsLoading(false)` gọi cả ở reject callback và catch block → confusing flow.

**File cần sửa:**

- `src/screens/ShareFormScreen.tsx`

**Cách thực hiện:**

1. Tách `isLoading` reset chỉ ở phần `finally` của outer try-catch
2. Trong `.catch()` của Promise, gọi `reject(error)` nhưng KHÔNG gọi `setIsLoading(false)`
3. Đảm bảo `setIsLoading(false)` chỉ ở 1 nơi: `finally` block của `handleShare`

```typescript
try {
  const hasPermission = await requestLocationPermission();
  if (!hasPermission) {
    setIsLoading(false);
    return;
  }

  await new Promise<void>((resolve, reject) => {
    // ... geolocation logic
    // Trong callback lỗi của geolocation, gọi reject(error) nhưng KHÔNG setIsLoading
  });
} catch (error: any) {
  Alert.alert('Error', error.message || 'Could not share document');
} finally {
  setIsLoading(false); // Đảm bảo luôn reset ở đây
}
```
